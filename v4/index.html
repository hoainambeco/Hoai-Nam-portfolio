How I engineer

Four habits, in the order a system meets them: from the first design to running in production.

  1. design

    Build for failure

    Production systems fail. Design them so a failure stays contained and the system can recover from it.

  2. build

    Keep complexity intentional

    Reach for distributed systems and new abstractions when they solve a real problem, not because they sound impressive.

  3. measure

    Measure before optimizing

    Find the bottleneck first. Then decide whether the architecture needs to change.

  4. operate

    Ship, observe, improve

    Engineering does not end at deployment. What happens in production decides what gets built next.
